Strivo Consultancy is an enterprise-grade, full-stack web application engineered to manage and streamline corporate consultancy operations, client engagement, talent acquisition, and content management.

1. System Architecture, Tech Stack & Deployment

The application follows a decoupled client-server architecture using a RESTful API pattern communicating over JSON.

Deployment & Hosting (Vercel)

Both the client and server codebases are fully deployed and hosted on Vercel:

  • Frontend (Client): Deployed as a high-performance static web application with edge-routing support.
  • Backend (Server): Deployed using Vercel Serverless Functions. The vercel.json configuration file at the server root directs incoming /api/* endpoints to the Node.js/Express server initializer (src/server.js), running them on demand.
  • Cloud Data Stores (Database): MongoDB hosted globally via MongoDB Atlas clusters.
  • Cloud Data Stores (Media Storage): Cloudinary holds static media assets, including candidates' resumes, CVs, and blog images.

Tech Stack Details

Frontend (Client)

  • Core Library: React 19
  • Build Tool: Vite (configured with lazy-loaded code-splitting for performance optimization)
  • Styling: Tailwind CSS v4, Material UI (MUI v5 with Emotion engine)
  • Routing: React Router DOM (v6) for declarative routing and dynamic path parameters
  • Animations: Framer Motion, OGL, React CountUp
  • Data Visualization: Recharts (for dynamic admin graphs and combined reports)
  • Notification Engine: Sonner & React-Toastify
  • Client State & HTTP: Axios (with custom request/response interceptors for automatic JWT propagation)

Backend (Server)

  • Runtime Environment: Node.js
  • Web Framework: Express.js (v5)
  • Database: MongoDB with Mongoose ODM (Object Document Mapper)
  • Security & Hashing: JSON Web Token (JWT) for stateless session handling, BcryptJS for cryptography/password hashing
  • File Management: Multer (in-memory buffers) and Cloudinary API (storage integration)
  • Email Engine: Nodemailer (configured with secure SMTP TLS)
  • Resume Parsing: PDF-Parse (for PDF extraction) and Mammoth (for raw DOCX XML extraction)

2. Core Modules (Frontend & Backend)

Frontend (Client) Modules

The frontend is divided into five main modules:

  1. Auth & Route Protection Module: Handles local storage of authentication states (adminToken, adminUser), configures custom HTTP-only request interceptors inside Axios to auto-inject Bearer tokens, and wraps restricted routes inside ProtectedRoute.jsx.
  2. Routing & App Shell Module: Manages URL state mappings and dynamic routes in App.jsx, sets up global lazy-loaded route boundaries, and handles page scroll behaviors (ScrollToTop).
  3. UI/UX Components Module: Shared reusable UI elements under src/Components/ such as Navbar.jsx, AdminNavbar.jsx, Footer.jsx, SEO.jsx, LoadingIndicator.jsx, ErrorBoundary.jsx, Ready.jsx, and dynamic dashboard elements (CaseStudyFilters.jsx, CaseStudyTable.jsx, CaseStudyStats.jsx).
  4. API Services Module: Located in src/services/ and contains outbound network communication helpers (allApi.js for CRUD operations, commonApi.js for generic HTTP requests, and cookieHelper.js / serverUrl.js for configuration).
  5. Page Modules: Page directories holding UI page files for both Client-Facing and Administrative Views.

Backend (Server) Modules

The backend is composed of six logical modules:

  1. Database Connection & Config Module (src/config/): Includes db.js (Mongoose connection to Atlas), cloudinary.js (Cloudinary API wrappers), and mail.js (Nodemailer SMTP transport protocols).
  2. Security & Auth Middleware Module (src/middlewares/): Houses authMiddleware.js which decodes incoming JWTs, matches user role claims, and enforces Role-Based Access Control (RBAC).
  3. API Routing Module (src/routes/): Maps incoming HTTP methods (GET, POST, PUT, DELETE) directly to respective controllers (e.g., adminRoutes.js, careerRoutes.js, caseStudyRoutes.js).
  4. Controllers Module (src/controllers/): Executes core business logic, orchestrates data validation, and structures standard JSON response payloads.
  5. Data Schemas & Persistence Models Module (src/models/): Declares Mongoose schemas representing database collections (e.g., Admin.js, CareerApplication.js, CaseStudy.js).
  6. Utility & Processing Parsers Module (src/utils/): Includes resumeParser.js to convert pdf/docx buffers into plain text and apply custom keyword filters.

5. Administrative Portal: Detailed Specifications (Admin Role)

A. Central Analytics Dashboard (Dashboard.jsx)

  • Objective: Serves as the primary operational tracking command center, keeping all system jobs, client feedbacks, pending moderation pipelines, and business metrics under control.
  • KPI Scorecard Tracker: Renders live indicator cards counting core system entries and incorporates a real-time server connectivity checker to alert administrators of server latency.
  • Business Analytics & Date Filtering: Integrates interactive Recharts (Area, Bar, and Line charts) with dropdown duration filters (All-Time, Last 30 Days, Last 7 Days).
  • Dossier Printing & Exporting: Implements a Dossier Print Engine that opens a clean layout view of the analytics grid and runs window.print() dynamically for offline tracking.
  • Today's & Pending Task Allocations: Tracks moderation tasks created "Today" versus "Older" pending items. Alerts the admin based on pending task counts.
  • Actionables Card: Aggregates counts of items needing attention (e.g., Draft Articles). Clicking an item opens the Actionable Details Modal for quick-approvals.
  • Client Review Moderation: Reviews submitted are saved as unapproved. Admins can click Approve (triggers PUT /api/reviews/:id) to display them on the Home page, or Delete to purge the feedback.

B. Customer Inquiries Board (Inquiries.jsx)

  • Objective: Manages customer inquiries submitted via /contact.
  • Detailed Inquiry Modal: Displays sender info and query message.
  • Backend Response Action Flow: Admins can execute one of five actions directly from the dropdown:
  • Reply by Email: Edit email copy and send to the client (transitions status to Responded).
  • Convert to Proposal: Opens an overlay to specify Subject, Budget, Timeline, and attach files before generating a PDF (transitions status to Proposals).
  • Assign to Team: Select a team member (Vishnu, Namitha, Najma) and email the client with representative details (transitions status to Responded).
  • Schedule Follow-up: Select a date to set nextFollowUp and email scheduling details to the client.
  • Mark as Closed: Marks status as Closed and emails a closure notification.
  • Dossier Printing: Compiles selected client metadata into a printable document view using @media print CSS overrides.
  • Inquiries Overview Cards: Tabbed views filter entries. Renders an interactive card grid tracking overall action details and status badges.

C. Articles & Insights CRUD Management

  • Objective: Manages the published corporate blog posts and market insights via ArticlesAdmin.jsx, CreateArticle.jsx, and EditArticle.jsx.
  • Content Editor: Form supporting text content, titles, categories, tags, and cover image. Uploads cover images directly to Cloudinary CDN.
  • Publishing Validation: The date picker restricts selection to today or future dates. If a future date is selected, the system automatically saves it as a Draft to withhold it from the public feed until the release date.
  • Actions: Draft, publish, edit (body copy, titles, images), and delete articles.

D. Case Studies CRUD Management

  • Objective: Create and display success stories via CaseStudies.jsx, CreateCaseStudy.jsx, and EditCaseStudy.jsx.
  • Data Fields: Title, industry category, statistical metrics, client summary, and cover layout.

7. Core Features & Business Logic

A. Authentication & Session Security

  • Credential Verification: Multi-field registration/login matching against usernames or emails case-insensitively using regex filters.
  • Password Policies: Strict regex enforcement (minimum 8 characters, 1 uppercase, 1 lowercase, 1 number, and 1 special symbol).
  • Stateless Sessions: JWT tokens are issued and saved in HTTP cookie buffers and LocalStorage. An Axios interceptor automatically appends the token as a Bearer header.
  • Password Recovery: OTP-based reset mechanism generating a 6-digit numeric OTP (hashed with a 5-minute expiration) sent via Nodemailer, followed by a temporary 10-minute JWT token for resets.

B. Resume Parser Utility (resumeParser.js)

  • Extracts text dynamically using pdf-parse for PDF files and mammoth for DOCX XML buffers. Runs extracted text against predefined keyword filters to score candidate legitimacy before database insertion.

8. Role-Based Access Control (RBAC)

Strivo implements strict role separation between Admin (Administrator) and HR (Human Resources) roles.

  • Client-Side Guard Rails (ProtectedRoute.jsx): Wraps administrative routes, reading the active session token and user profile object.
  • Client-Side HR Boundaries: Blocked from accessing the global Admin Dashboard, client inquiries, case studies, or articles. Attempted access redirects them to /admin/career.
  • Client-Side Admin Boundaries: Complete, unrestricted navigation access across all panels.
  • Server-Side Authentication (protect middleware): Verifies the integrity of the JWT from HTTP-only request cookies, falling back to headers or query parameters. Retrieves user profile fields while keeping passwords secret.
  • Server-Side Authorization (authorize middleware): Accepts role permissions as an array. Ensures that requests originating from unauthorized roles return a 403 Forbidden response block.

10. Conclusion & Future Roadmap

Strivo Consultancy delivers a robust, enterprise-ready digital workspace that streamlines client onboarding, recruitment pipelines, and administrative content moderation.

Key Achievements
